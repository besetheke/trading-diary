# AP-15 · Umzug auf den Server

Ziel (Zielbild „Rechner“): Entwicklung und Paper-Tests bleiben auf **NOX**, der Betrieb
läuft auf dem **Server**. Dort wird nicht entwickelt; der Stand kommt per Git
(GitHub, Branch `master`) und `werkzeuge\server\Deploy.ps1`.

Vorbereitet (13.10.2026): `Deploy.ps1` (Erstinstallation, Update, Trockenlauf),
`options-roller\Start-Dienst.ps1` / `Beenden-Dienst.ps1`, Einstellungen des Rollers je
Rechner in `config.json` (Vorlage `config.beispiel.json`), `python -m roller.pruefung`,
`Schnellstart.ps1` startet den Roller mit, `strategie_lauf pt-stornieren` für den Wechsel.

## Grundregeln

- **Ein Roller je Konto.** Nie zwei Roller-Dienste gleichzeitig gegen dasselbe Konto
  (beide clientId 3). Erst auf NOX beenden, dann auf dem Server starten.
- **Eine Paper-Anmeldung, ein Ort.** Die Paper-TWS zieht mit auf den Server.
- **Marktdaten:** Live- und Paper-TWS auf demselben Rechner (gleiche IP). Läuft die
  Live-TWS auf einem anderen Rechner als die Paper-TWS, bekommt Paper keine Daten
  (Befund 13.10.2026, Fehler `162 … different IP address`). Mit geteilten Abos bekommt
  Paper Live-Daten, die Live-TWS dann aber nicht — Standard: nicht teilen, Paper arbeitet
  mit verzögerten Daten.
- **Nichts wird gelöscht.** NOX bleibt bis zur Abnahme unverändert lauffähig (Rückweg).

## Schritt 1 · NOX vorbereiten

1. Alle Repos sauber und gepusht: `trading-diary`, `options-roller`, `momentum-lab`
   (`git status` leer, `git push`). Die BO Research Suite hat kein Remote — Ordner kopieren
   (nur lesend eingebunden, AP-14c).
2. Sicherung der Journal-Datenbank: `backup.cmd journal.db backups\vor-umzug.db`.

## Schritt 2 · Server einrichten (einmalig)

1. Programme: Python 3.12 (64 bit, „Add to PATH“), Git, Node.js LTS (für die Oberfläche),
   TWS (Live und Paper), **TWS API „Latest“ nach `C:\TWS`** (liefert `ibapi`).
2. Code: `git clone https://github.com/besetheke/trading-diary.git C:\10_Coding\trading-diary`,
   dann `C:\10_Coding\trading-diary\werkzeuge\server\Deploy.ps1 -Erstinstallation`
   (klont die übrigen Repos, richtet `.venv`, `ibapi`, Oberfläche ein).
3. TWS-API-Einstellungen (Live **und** Paper): „ActiveX- und Socket-Clients aktivieren“;
   Live **Port 7496 mit „Schreibgeschützte API“**; Paper **Port 7497, nicht schreibgeschützt**;
   „Verbindungen nur von localhost“. Automatischer Neustart der TWS täglich (TWS-Einstellung
   „Auto Restart“), damit die Sitzung nicht abläuft.

## Schritt 4 · Wechsel (Cutover)

1. **NOX:** Profit-Targets stornieren und Dienst beenden — sie werden auf dem Server neu
   gesetzt (Wiederanlauf-Abgleich):
   ```
   cd C:\10_Coding\options-roller
   .\Beenden-Dienst.ps1
   .venv\Scripts\python -m roller.strategie_lauf pt-stornieren --ausfuehren
   ```
   Paper-TWS auf NOX abmelden.
2. **Server:** `ketten.json` aus Schritt 3 an seinem Platz; Paper-TWS anmelden;
   `Schnellstart.ps1` (startet Journal und Roller). Beim ersten Prüflauf meldet der Roller
   „Profit-Target … nicht mehr offen — wird neu gesetzt“ je Kette (Mail) — so gewollt.
3. **Prüfen:** `options-roller\.venv\Scripts\python -m roller.pruefung --tests` ohne FEHLER;
   Station → Roller zeigt alle Ketten mit Delta und Profit-Target; TWS (Paper) zeigt die
   neuen GTC-Orders mit `orderRef R3|…`.

## Schritt 5 · Betrieb einrichten (Aufgabenplanung)

- **Nachtlauf** (Flex-Abruf, Rebuild, Sicherung): `trading-diary\nachtlauf.cmd`, täglich,
  wie auf NOX (START.md, „Nächtlicher Abruf“). Auf NOX danach **deaktivieren**, sonst
  laufen zwei Abrufe.
- **Station bei Anmeldung:** Aufgabe „bei Anmeldung“ → `powershell -ExecutionPolicy Bypass
  -File C:\10_Coding\trading-diary\Schnellstart.ps1` (startet Roller und Journal, öffnet den
  Browser). Die TWS braucht eine angemeldete Sitzung; ohne Anmeldung kein Roller.
- **Sicherung:** `FLEX_BACKUP_ZIEL` und Cloud-Ziel in `flex.cmd` auf Server-Pfade prüfen.

## Schritt 6 · Updates

Entwicklung auf NOX → Tests grün → commit → `git push`. Auf dem Server:

```
C:\10_Coding\trading-diary\werkzeuge\server\Deploy.ps1 -Trocken   # was passiert
C:\10_Coding\trading-diary\werkzeuge\server\Deploy.ps1            # anhalten, holen, migrieren, starten, prüfen
```

Das Skript bricht ab, wenn auf dem Server lokale Änderungen liegen, sichert `journal.db`
vor jeder Migration und startet den Journal-Server neu (nach API-Änderungen nötig).

## Abnahme

1. `roller.pruefung --tests` auf dem Server ohne FEHLER.
2. Station auf dem Server zeigt Journal, Roller (alle Ketten), Momentum Lab, System.
3. Ein Nachtlauf auf dem Server erfolgreich (Log), auf NOX keiner mehr.
4. Ein Roll oder eine Eröffnung am Paper-Konto vom Server aus, mit Mail.
5. Rückweg dokumentiert: NOX unverändert startfähig (Dienst dort nur aus).

## Offen

- Läuft die Live-TWS heute auf dem Server? Dann bleibt sie dort, und die Paper-TWS
  kommt dazu. Wenn nicht: wo läuft sie, und wer nutzt sie (Hauptanwendung)?
- Windows-Benutzer auf dem Server (eigener Benutzer für die Station? Der Mail-Tresor
  ist an den Benutzer gebunden).
- Remote-Zugriff auf die Station vom NOX/Handy: derzeit nur `127.0.0.1`. Freigabe im LAN
  wäre ein eigenes Paket (Zugriffsschutz nötig — die Station kann Orders auslösen).
