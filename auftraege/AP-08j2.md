# AP-08j2 · Kalender-Seite und API-Endpunkt kollidieren

Abnahmebasis (vom starken Modell, bereits eingecheckt):
`tests/test_ui_routen.py` — drei Tests, zwei davon sind heute rot.

## Befund (Probelauf 09.10.2026 gegen eine Kopie von `journal.db`)

Die Oberfläche hat die Seite `/kalender`, die API den Endpunkt
`GET /kalender?monat=…` (AP-07t, Tests unveränderlich). Ein Neuladen oder
Lesezeichen der Seite erreicht den Endpunkt statt der Oberfläche: Der Browser
zeigt den JSON-Fehler 422. Die anderen Adressen (`/`, `/positionen/:chainId`,
`/tag/:datum`) sind in Ordnung, die API heißt dort `/tage/…`.

## Zu ändern

1. **Die Seite der Oberfläche bekommt die Adresse `/monat`** (statt
   `/kalender`): `ui/src/main.tsx` (Route und Navigations-Verweis) und
   `ui/src/Tag.tsx` (zwei Verweise „Zum Kalender"). Der Anzeigetext
   „Kalender" bleibt. Der API-Endpunkt `/kalender` bleibt unverändert.
2. **`ui/vite.config.ts`:** Die Proxy-Einträge für `npm run dev` um die neuen
   API-Wege ergänzen (`/tage`, `/kalender`, `/journal`, `/tags`), damit die
   Entwicklungsumgebung dieselben Anfragen erreicht. Achtung: Im Entwicklungs-
   server darf der Proxy nur Anfragen mit dem API-Muster abfangen, nicht die
   Seite `/monat` — daher bleibt die Seite unter `/monat`. Nichts am Bau
   (`vite build`) ändern.
3. **Neu bauen** (`npm run build`, Bauort wie bisher dokumentiert), damit
   `ui/dist` die neue Adresse trägt.

## Grenzen

Keine Änderung an `api/`, `tests/`, `fixtures/`, `journal/`, `engine/`. Keine
neue Abhängigkeit.

## Abnahme

`tests/test_ui_routen.py` grün, `npm run build` fehlerfrei, Gesamtsuite grün,
`ruff check .` sauber. Das starke Modell prüft danach die Adressen noch einmal
gegen die laufende Anwendung auf einer Kopie von `journal.db`.
